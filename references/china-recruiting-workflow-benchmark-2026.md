# 中国互联网招聘工作流基准

更新时间：2026-05-19

这份文件不讲招聘理论，只回答一件事：

`中国互联网公司里，招聘工作流一般到底怎么跑，主流 HR SaaS 在系统里怎么建这条链路。`

它用于检验当前 recruiting skill 的工作流是不是专业，而不是只看起来像。

## 一、当前互联网公开资料里，主流 ATS / HR SaaS 的共同结构

### 北森公开招聘流程

来源：

1. 北森
   [招聘管理系统](https://www.beisen.com/product/recruitment/)

截至 2026-05-19，北森公开展示的主流程包括：

1. 招聘需求管理
2. 职位广告 / 发布
3. 简历筛选
4. 面试协同
5. 业务协同
6. Offer 与入职
7. 多角色协同
8. 数据分析

北森公开资料里还强调：

1. 对接 170+ 外部招聘渠道
2. 简历资源统一收集、查重合并、投递留痕
3. 从职位发布、简历筛选、结构化面试，到 Offer 发放、入职管理形成闭环

这意味着：

1. 一个专业招聘 skill 至少要覆盖 `筛选 -> 面试反馈 -> Offer 前置 -> 回写`
2. 不能只停留在“帮我写一句话”

### Moka 公开招聘流程

来源：

1. Moka
   [Moka 主页 / 试用页](https://www.mokahr.com/trial/)
2. Moka
   [数据无缝流转：一体化 HR 系统实现招聘到入职闭环的路径](https://www.mokahr.com/blog/29553.html)

截至 2026-05-19，Moka 公开资料里强调的链路包括：

1. 社会招聘流程优化
2. 招聘自动化
3. 招入一体
4. 招聘到入职的数据无缝流转
5. 候选人唯一数字档案
6. 面试评价、Offer 详情、入职状态的统一存储
7. 入职材料完整性校验和补传提醒

这意味着：

1. 招聘 skill 不该只生成“内容”
2. 还应该生成“能进入下一环节的结构化材料”
3. 例如面试纪要、Offer 前置摘要、材料缺口提醒、tracker 回写

## 二、当前 recruiting skill 的工作流，哪些是专业的

截至 2026-05-19，当前 recruiting repo 已经比较像专业招聘微工作流的部分有：

1. `JD + 简历 -> 初筛 -> 面试重点 -> 候选人话术 -> tracker`
2. `面试反馈 -> 归一化 -> 推荐结论 -> 候选人话术 -> tracker`

这两条链路专业的地方在于：

1. 都从真实工作触发点开始
2. 都不是纯知识问答
3. 都能把零散输入转成结构化输出
4. 都带回写结果

这已经比“招聘 SOP 生成器”强很多。

## 三、当前 recruiting skill 不够专业的地方

问题不在于“没有功能”，而在于“专业依据层太薄”。

### 1. 没有真正的招聘判断知识底盘

现在更多是在做：

1. 输入归一化
2. 结构化输出
3. 合理语言组织

但还不够像真正资深招聘 HR 的地方在于：

1. 对 JD 硬性条件和加分项的权重模型还不够明确
2. 对面试轮次差异没有独立处理规则
3. 对“分歧反馈如何定性”为推进、补面还是保留，规则还不够稳
4. 对 Offer 前置材料的预算和组织口径尚未真正连起来

### 2. 缺少互联网招聘里的典型业务判断库

比如当前还没有显式沉淀这些判断：

1. 产品岗和技术岗初筛关注点不同
2. 业务面和专业面冲突时谁优先
3. 哪些 feedback 属于硬性 blocker
4. 哪些 feedback 只是 soft concern
5. 什么情况下应该建议“补一轮而不是直接拒绝”

### 3. 缺少与真实 ATS 字段的一致性约束

虽然现在有 `record_update`，但还没有细化到：

1. 候选人阶段字段怎么映射
2. 反馈状态怎么映射
3. 面试轮次命名怎么统一
4. 拒绝原因或保留原因如何标准化

## 四、所以专业 workflow 长什么样

如果按照中国互联网招聘的真实链路，一个专业的 recruiting skill 最少应具备这条骨架：

1. `Trigger`
   收到 JD、简历、面试反馈、审批需求中的任一触发点
2. `Read`
   读取材料，允许脏输入
3. `Normalize`
   归一化候选人、岗位、轮次、反馈字段
4. `Judge`
   做出推进 / 保留 / 补面 / 拒绝 / Offer 前置建议
5. `Explain`
   给出判断依据和分歧点
6. `Generate`
   生成候选人消息、内部摘要、面试问题或审批说明
7. `Write Back`
   输出 ATS / 表格可回写记录
8. `Archive`
   形成可下载纪要或结构化 JSON

这也是为什么当前 skill 里最值得保留的不是“解释文案”，而是这条结构化链路。

## 五、对当前 recruiting skill 的真实评价

截至 2026-05-19：

1. 工作流骨架方向是对的
2. 已经比“全流程资料库”更专业
3. 但判断知识库层还不够厚
4. 目前更像 `workflow prototype + output formatter`
5. 还没有到 `professional recruiting judgment engine`

## 六、接下来最值得补的不是更多场景，而是知识底盘

优先级建议：

1. 做 `JD 判断规则库`
   按岗位族拆 must-have / nice-to-have / blocker
2. 做 `面试反馈定性规则库`
   拆能力、经验、动机、沟通、稳定性、薪资风险
3. 做 `ATS 字段映射库`
   明确 stage、decision、risk、next_action 的标准值
4. 再做 `Offer 前置判断库`
   让审批建议不只是文案，而是有预算和字段完整性依据

如果不补这几层，skill 看起来像工具，但本质上还只是“格式化助手”。
